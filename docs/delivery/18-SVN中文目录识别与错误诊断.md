# SVN 中文目录识别与错误诊断（0.1.11）

用户报告 E155007，日志中的中文路径显示乱码。当前尚无目标 Windows/Cloudaemon 实机复现，不能将乱码认定为工作副本识别失败的根因。

## 已确认并修复

- 旧版把子进程输出统一按 UTF-8 有损解码。新版优先 UTF-8，遇到非 UTF-8 字节时在 Windows 按系统 ANSI 代码页转换；只影响输出解码，不修改输入路径。CP936 转换测试已纳入 Windows 编译检查，未在 Windows 执行。
- SVN 工作副本检查由当前目录 `.` 改为显式绝对目标，已版本化文件检查及提交也使用绝对路径；不 canonicalize、不转换成沙箱外物理路径。所有本地 SVN 目标追加空 peg revision，避免文件名中 @ 被解析为修订号。
- 运行记录新增所选 svn.exe、原始 Unicode 目录、最近可见 .svn/_svn 管理目录、wc.db 可读性与 SQLite 文件头诊断。只读检查不等同于 SVN 工作副本有效性校验。
- 执行前检查失败时也返回上述上下文。没有自动 checkout、upgrade、cleanup 或重新建立工作副本。

## 验证

插件宿主 10 项本机测试通过。端到端回归使用含中文与空格的 SVN 工作副本目录，执行真实 Git 合并/push、ZIP、SVN commit；另验证普通目录返回 E155007 且附带可读上下文。所有仓库均为临时本地仓库，未访问业务远端。

Windows 测试代码交叉检查与 0.1.11 开发版打包通过；目标沙箱执行待用户验证。插件包 API/流程未改变，升级宿主即可保留已安装插件及配置。

## 现场下一步

1. 升级 0.1.11，先点「执行前检查」，无需运行实际同步。
2. 核对诊断中的 SVN 客户端及原始 Unicode 目录是否为预期值。
3. 若未发现管理目录，检查沙箱内此目录及其父目录是否可见 .svn（隐藏目录），是否确为已 checkout 的工作副本。
4. 若 wc.db 可读但同一客户端仍报 E155007，在同一沙箱用同一路径的 svn.exe 执行 `svn info -- "目录绝对路径@"` 对照；提交完整诊断。不要删除 .svn、重建工作副本或在沙箱外路径上尝试提交。

绝对路径的选择参考 Apache Subversion FAQ 对 Windows APR 路径处理的说明：https://subversion.apache.org/faq.html 。本报告未确定原报错由路径长度造成。
