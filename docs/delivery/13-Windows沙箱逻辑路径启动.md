# Windows 沙箱逻辑路径启动（0.1.6）

日期：2026-11-22。

## 问题与边界

用户验证：Cloudaemon 沙箱中所显示的 C 盘路径属于沙箱逻辑文件视图，底层有独立工作空间；手动启动 Git Bash 正常，小工坊启动不一致。本机无法复现该 Windows 沙箱，不能将该描述或普通 CI 结果当作已经定位 Cloudaemon 内部实现。

0.1.5 仅移除了替换解释器的逻辑，但仍存在 canonicalize、cygpath 子进程、Bash 二次入口和 PATH 注入。0.1.6 移除这些干预，为实际环境保留原始启动入口和逻辑文件命名空间。本文件取代 0.1.4 中 Bash 预检与真实路径比较相关行为描述。

## 实现

- 直接创建配置的解释器，不搜索同安装目录的替代程序。
- 使用原逻辑脚本绝对路径，仅将分隔符转换为正斜杠及规范化 Windows 长路径语法前缀。C:/、D:/ 和 UNC 的逻辑盘符/共享名保持；不猜测 /c、/d 挂载，不解析为沙箱底层路径。
- 不再运行额外 cygpath 进程，不 canonicalize 工作目录，不在命令构造阶段额外打开脚本。
- 移除 --noprofile/--norc、Bash 固定入口及 exec 第二层 Bash；不移除 BASH_ENV/ENV/PWD，不再自动注入 PATH。使用解释器自己的初始化行为；直接使用 usr/bin/bash.exe 的任务如需额外工具，应显式配置 PATH 或选择本身负责初始化的 Git 启动器。
- 继承主程序环境，仅应用用户配置的环境变量覆盖。当前进程创建仍为直接子进程，不使用宿主服务、管理员提升、ShellExecute、BREAKAWAY 或已存在的外部终端转发。
- 文件存在性、绝对路径和工作目录验证仍由小工坊进程自己的文件视图执行。它不证明子进程继承了相同视图；删除了执行记录中的“Windows 读取检查通过”表述，改为记录请求逻辑路径和“沙箱继承未验证”。
- 挂起创建、Job 管理、取消、超时和日志采集机制保留，不通过无管理运行绕过沙箱或静默退化。如果加入 Job 失败，明确报错，不伪报已执行。

## 回归

本机后端 12 项、前端 17 项测试通过；Windows 测试代码交叉编译通过。新增 Windows 回归覆盖无物理文件时的命令构造、盘符保留、自定义工作目录、中文/空参数/字面变量参数、默认不编辑环境、显式 PATH 覆盖、UNC 及长路径语法。真实 Git Bash D 盘回归使用逻辑绝对路径和显式工具环境，不再依赖内部入口或预检标签。

上述验证不包含 Cloudaemon 本机验收，Windows 专用测试在 macOS 只编译未执行。Git 官方启动器仍可能在内部执行自己的路径解析和创建子进程；小工坊无法保证所有第三方运行时自动继承沙箱。

## 实机验收

彻底退出旧版托盘进程，在 Cloudaemon 内安装/启动 0.1.6。保留原 git-bash.exe 和脚本逻辑路径，分别手动执行与定时触发，确认读取已知仅存在于沙箱的文件并核对脚本真实结果。不要改成沙箱底层存储路径。终端启动器输出不一定进入管道，窗口或启动器退出也不能单独证明脚本完成。

若仍失败，应结合完整执行消息和 Cloudaemon 官方对该解释器/子进程的纳管策略继续定位，不再自动猜盘符或替换解释器；也不宣称随包内置 Bash 即可解决隔离继承。
