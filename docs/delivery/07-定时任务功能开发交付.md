# 定时任务功能开发交付

日期：2026-11-20。本轮将定时任务从独立模拟原型接入正式小工坊 App。实现按既有原型默认策略落地；可调整的策略扩展不混入本轮。

## 使用入口

打开 `builds/darwin-arm64/HandyKit.app`，选择侧栏「时间与任务 → 定时任务」。该工具沿用唯一 Tab，切换到其他工具不会终止后台计划；关闭有修改的任务 Tab 会提示放弃修改。

1. 点击「新建任务」，填写名称。
2. 在执行计划中选择常用周期、自定义五字段或高级表达式，填写 IANA 时区。右侧显示 Rust 计算的中文说明与未来十次；输入无效时立即清除旧结果。
3. 选择脚本、可执行程序或应用，选择本机目标与解释器，逐行添加独立参数。受管动作可配置工作目录和环境覆盖。
4. 核对策略，保存为暂停，或保存并启用。启用后按计划真实执行。
5. 「立即执行」仅使用已保存的配置，并明确确认真实执行；详情支持复制和删除。执行记录可分页、按任务筛选，查看实时输出、完成结果、退出码和脱敏快照；运行中的受管任务可停止本轮。

## 已实现行为

|部分|行为|
|---|---|
|任务管理|新增、编辑、版本冲突检查、复制为暂停、启用、暂停、软删除、名称搜索、动作与启停筛选；无模拟任务预置|
|Cron|Unix 五字段；数字、星号、列表、范围、步长；星期 0/7 均表示周日；不自动接受 Quartz 或英文别名|
|可视化|每 N 分钟、每小时、每天、每周多选、每月日期列表；字段级每个值/列表/范围/步长；组合语法无法无损回填时保持高级模式|
|时间语义|独立 IANA 时区；日期与星期均限制时 OR；缺失本地时刻跳过，重复本地时刻只选首次；无对应月日不挪动|
|真实动作|受管脚本/本机程序，按 argv 顺序传参；工作目录默认目标所在目录；不解析一整条 shell 命令，不展开变量或通配符|
|应用启动|macOS 使用 `/usr/bin/open -a`，支持新实例请求及参数；Windows/Linux 启动独立原生程序。只标记「启动请求成功」，不等价于内部工作完成|
|后台与去重|Rust 线程调度，与 WebView 活跃状态无关；单实例插件恢复已有窗口；用户数据目录文件锁排除第二调度所有者；计划记录唯一约束防同版本同触发重复派发|
|并发与遗漏|同任务重叠跳过；全局上限 3；不排队、不重试、不补跑；新分钟触发宽限 30 秒。检测到时间间隔时显示遗漏摘要；回拨不重复当前运行期已检查分钟|
|超时与取消|受管任务可配置 1–604800 秒超时；Unix 独立进程组，Windows 先挂起、纳入 Job 再恢复；停止只作用于本轮受管组，不关闭独立应用|
|退出|关闭窗口继续托盘驻留；彻底退出时如有运行任务，选择继续后台、等待完成后退出或停止后退出。等待退出期间停止新调度|
|恢复|重启保留定义和记录；旧 running 记录标记「中断 / 结果未知」，不自动重跑。原型 localStorage 数据不导入真实执行库|
|日志与容量|stdout/stderr 分开、实时查询；持续读取但单轮合计最多保留 10 MiB；历史保留不超过 30 天/10000 条，历史输出约 200 MiB 超出时从旧记录清除并标记截断|

任务总数上限 500；单定义最多 512 KiB。敏感标记仅遮罩界面、脱敏执行快照；定义中的值为了重启调度以明文写入 SQLite，界面有明确说明。任意目标程序的输出不能保证自动脱敏。运行中输出暂存于有界内存，完成时落库；异常退出可能丢失本轮未完成输出。数据库空闲页由 SQLite 复用，删除历史不代表磁盘文件立即缩小。

## 工程入口

- `development/crates/scheduler/`：独立 Rust 核心，包含 Cron、SQLite、执行器和调度服务；可以不安装 Tauri GUI 依赖单独测试。
- `development/apps/desktop/src/tasks/`：正式 TypeScript 页面、组件样式、退出交互与页面测试。
- `development/apps/desktop/src-tauri/src/tasks.rs`：任务 IPC、真实文件选择、平台查询、退出控制。
- `database/migrations/0002_timer_runtime.sql`：新建真实任务及运行表，不修改旧迁移。

数据路径由 Tauri `app_data_dir()` 决定，macOS 为 `~/Library/Application Support/dev.handykit.desktop/handykit.sqlite3`。其他平台遵循各自的应用数据目录；不写入安装包或源码目录。Rust 校验已应用迁移的 SHA-256；已有库升级前通过 SQLite backup API 备份，校验或备份失败时不启动调度。旧提醒表完整保留，未默认为可执行任务。

IPC 包括 `timer_overview`、`timer_preview`、`timer_save`、`timer_toggle`、`timer_delete`、`timer_run`、`timer_cancel`、`timer_history`、`timer_run_detail`、`timer_pick`、`timer_platform`、`timer_shutdown`、`timer_confirm`。没有通用 shell 字符串执行接口。前端浏览器开发模式明确提示需运行 App，不会以模拟执行冒充真实结果。

## 验证与边界

```sh
cargo test --manifest-path development/crates/scheduler/Cargo.toml --locked
npm test --prefix development/apps/desktop
npm run build --prefix development/apps/desktop
python3 -m unittest discover -s scripts/tests -v
python3 scripts/check_design_system.py
# 在桌面项目中打本机开发包
cd development/apps/desktop
npm run package:local -- --offline
```

本地核心测试包含真实临时 sh 脚本、独立/空/中文参数、环境覆盖、输出与退出码、重叠、全局饱和、超时、取消、后台计划派发去重、暂停、遗漏宽限、时钟回拨、配置版本、删除保留历史、迁移备份/校验、中断恢复与大输出上限。页面 DOM 测试校验保存/真实执行 IPC 边界、过期预览清除、日志转义和关闭草稿；它不等价于原生 GUI 实机验收。

GitHub Checks 增加 macOS、Linux、Windows 核心矩阵；Windows 专用测试使用测试 exe 验证 Job 管理与超时。发布工作流仍仅在版本标签或显式发布操作时打平台安装包，开发提交不创建发布版本。

尚需各平台实机确认：系统文件选择器、应用启动/复用与传参、隐藏窗口后实际整分钟触发、托盘退出对话框、键盘与视觉验收。人为脱离进程组/Job 的守护程序不属于受管任务承诺；启动器不应通过受管脚本后台逃逸，应使用独立应用模式。SIGKILL/断电无法执行正常退出流程；Unix 崩溃时外部进程结果可能未知，不承诺外部动作严格执行一次。

未实现扩展：秒级/Quartz、系统退出后执行、登录自启、PowerShell/bat/WSL/.desktop 专用适配、自动重试、队列/补跑、自定义全局容量设置、系统凭据加密存储、跨 App 重启的编辑草稿恢复。

API 参考：[chrono-tz](https://docs.rs/chrono-tz/latest/chrono_tz/enum.Tz.html)、[rusqlite](https://docs.rs/rusqlite/latest/rusqlite/struct.Connection.html)、[Tauri 原生文件选择](https://docs.rs/tauri-plugin-dialog/latest/tauri_plugin_dialog/struct.FileDialogBuilder.html)。
