# Git → ZIP → SVN 原生同步插件

`code-sync.hkp` 是可独立安装、停用、卸载的插件包，要求小工坊 0.1.10。它转换仓库中 `sync_code-merge-debug.sh` 的业务流程，不是通用 Shell 转译器。

## 使用

1. 安装 0.1.10，进入「插件管理」安装本目录的 `.hkp`。
2. 打开插件，导入原 `config.sh` 与 `repository.ini` 所在目录，检查工作目录、SVN 工作副本、Git/SVN 程序及分支。Windows 使用当前沙箱中可见的原生路径，不猜测物理盘映射。
3. 先执行前检查，再手动同步并核对远端提交。检查只验证本地环境，不证明远端认证成功。
4. 如需定时执行，创建暂停计划；停用原 sh 计划，再到「定时任务」确认配置版本并启用。

## 执行与边界

API 2 插件包声明原生工作流：按仓库克隆、可选合并（recursive / theirs）、push、ZIP、清理成功克隆；所有仓库处理后覆盖 SVN 中对应的已版本化 ZIP 并 commit。宿主提供受限原生操作，不执行 Shell。仍需本机可用的 Git/SVN 可执行程序，无需 Bash 或外部 zip。

ZIP 包含隐藏文件和 `.git`，采用原生压缩与临时文件发布；符号链接、特殊文件和非 UTF-8 文件名会停止并保留现场。实现使用 ZIP64 API，大于 4 GiB 文件尚未进行实际回归。不会自动 svn add/update。已有目标克隆目录或 ZIP 阻止执行，避免覆盖遗留现场。

同一宿主只允许一个原生同步。取消、超时和失败保留可核对的状态及产物；Git push 或 SVN commit 中断时标为未知，不自动重试或回滚。Git 已推送而 SVN 失败时，Git 改动仍然存在。历史保存 Git HEAD、各阶段状态、插件版本与工作流；程序意外退出的运行标为中断。

## 配置与认证

导入只解析静态赋值与 INI，不 source、不执行 config.sh，动态变量与命令需手动迁移。业务配置保存后以插件配置为准，修改原文件后需重新导入。

有 svn_password 时，导入默认引用原 config.sh：只保存路径，运行时静态读取口令，不复制到插件配置、计划或历史。该文件仍由用户管理，必须是静态赋值文件。也可清空引用使用已有认证缓存；手动执行支持一次性口令。口令经标准输入传递给 SVN，不放入 argv；URL 不接受嵌入口令。Git 使用已有认证机制。

计划绑定配置版本；修改配置、停用或卸载插件会暂停关联计划。更新版本并确认后再启用。卸载保留本机配置与历史。API 1 诊断插件继续兼容。

自动回归仅使用临时本地 Git/file:// SVN 仓库，验证真实合并冲突、推送、压缩、提交、失败保留与取消。Windows 交叉编译通过不代表 Cloudaemon 业务环境验证通过，首次请手动运行并核对真实远端结果。
