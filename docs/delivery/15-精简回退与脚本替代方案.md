# 精简回退与脚本替代方案（0.1.8）

日期：2026-11-22。

## 本次交付

用户实测内置 Bash 同样无法解决 Cloudaemon 内的执行问题。0.1.8 移除内置 Bash、PortableGit 资源映射、准备脚本、CI/发布下载步骤和解释器模式选项，恢复用户配置的外部解释器入口，保留 0.1.6 的逻辑路径处理。历史 0.1.7 包和构建依赖移出当前资源目录并归档，不影响新包。

数据库和历史记录保留，不自动改写用户任务。若已有任务使用 `builtin:bash`，新版给出「内置 Bash 已移除，请编辑任务并重新选择外部解释器」，界面显示空的解释器选择框及说明。该任务必须重新选择外部解释器后保存；不会自动使用宿主 Git 或继续执行已撤回运行时。

新包只包含小工坊程序，不含 Bash、Git 或 MSYS DLL。在线安装器缺少 WebView2 时仍需联网安装；独立 exe 需要已有 WebView2。升级时可按安装器的「先卸载旧版本」流程清理旧应用资源，保留用户数据；便携使用请解压到新目录，单纯覆盖 exe 不会释放旧目录中原运行时占用的空间。新版不会扫描删除用户目录或历史开发包。

验证：后端 13 项、前端 18 项测试通过，Windows 测试代码交叉编译通过。原配置重选外部解释器、已移除模式明确拒绝和旧记录保留均有回归覆盖；Windows/Cloudaemon 实机效果未在本机验证。

## 现有脚本实际工作

以仓库中的 `development/examples/code-sync/sync_code-merge-debug.sh` 为依据，其业务不是通用 Shell 交互，而是固定流程：加载配置及仓库清单 → clone 指定分支 → 可选 fetch/merge → push → 生成 ZIP → 复制到 SVN 工作副本 → SVN commit → 清理本轮临时目录并记录日志。

其中 `config.sh` 当前通过 source 执行，本身可能包含 Shell 代码。任何非 Bash 方案都不能承诺自动兼容任意 config.sh；应将必要配置整理为 INI/JSON 或表单，遇到动态 Shell 语句明确提示人工迁移。

## 两种替代路线

| 路线 | 实现方式 | 成本与适用边界 |
|---|---|---|
| PowerShell 改写 | 文件、配置、ZIP 使用 Windows/.NET API；Git/SVN 先调用原生 exe | 较快，不需要 Bash/MSYS；仍包含 PowerShell 及 Git/SVN 子进程，不能保证解决沙箱继承 |
| 小工坊原生同步任务 | 配置、文件和 ZIP 直接在小工坊进程中处理；Git/SVN 逐步使用链接库 | 较高，适合长期维护；可以减少 Shell 和子进程依赖，但必须先证明小工坊本身可见目标文件 |

### PowerShell：低成本验证路线

需要重写为真正的 `.ps1`，不能将 `.sh` 改后缀。当前小工坊可用「运行程序」动作调用 PowerShell，无需新增解释器适配：

- 程序：本机实际的 `powershell.exe`，例如 `C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe`。
- 有序参数逐项填写：`-NoProfile`、`-NonInteractive`、`-File`、`C:\脚本目录\sync-code.ps1`。
- 工作目录：脚本逻辑目录；使用现有超时与日志。

不要把 PowerShell 配置成当前「运行脚本」的 Bash 风格解释器，因为该入口传入的是 `-- <脚本>`，并非 PowerShell 的 `-File` 协议。脚本应检查每次原生命令的退出码并明确退出，避免 Git/SVN 失败而 PowerShell 最终返回成功。

ZIP 行为必须核对。原脚本的 `zip -r` 会包含目录内的隐藏内容；微软文档说明 `Compress-Archive` 会忽略隐藏文件/目录，且存在文件大小限制，不应不经验证直接替换。可使用显式枚举的 .NET ZIP API，逐项核对目录根层级、隐藏文件、文件名编码及大文件。

建议先写只读的 PowerShell 路径探针，仅检查原来那个沙箱内文件，再决定是否转换完整业务。若 PowerShell 子进程也不可见，继续换脚本语法没有证据支持。

### 原生任务：推荐的长期方向

先在小工坊主进程内只读验证同一个已知沙箱文件。如果主进程本身不可见，原生重写也不会自动解决隔离；应先确认 Cloudaemon 的文件授权和受支持启动入口。

若主进程可见，则按以下边界实现：

| 现有内容 | 原生实现方向 | 必须保持的语义 |
|---|---|---|
| config.sh、repository.ini | 结构化配置与显式校验 | 必需字段、仓库顺序、可选 mergebranch；不执行任意配置代码 |
| mkdir/cp/rm、日志 | Rust 文件 API 与现有执行记录 | 仅操作本次创建的临时目录；同名目标已存在则保留；失败保留现场 |
| zip -r | Rust ZIP 库 | 保留原目录层级和隐藏内容；不得遗漏 `.git` 等原先被打包的文件 |
| clone/fetch/merge/push | libgit2 或先验证原生 git.exe | 分支引用、认证、提交身份、错误处理；`recursive -X theirs` 必须做结果对照，不能简单理解成覆盖所有本地文件 |
| SVN copy/commit | libsvn_client 或先验证 svn.exe | 指定工作副本及文件、提交日志、超时；不擅自 svn add/update，不提交其他文件 |
| 定时、取消、执行日志 | 对接现有 Scheduler，增加原生任务类型 | 阶段状态、停止边界、每个仓库的结果；网络操作中止后的结果不伪报 |

只把 Bash 改成 `git.exe`/`svn.exe` 串联，仍然是子进程方案。若目标是尽量消除子进程视图差异，需要进一步使用 Git/Subversion 客户端库，并验证认证和传输配置不会再次启用外部 SSH、凭据助手或其他命令。库和 CLI 的行为也需要对照，不能宣称完全等价。

建议顺序：主进程与 PowerShell 的只读文件可见性对照 → 选择实现路线 → 使用合成配置和临时仓库验证 → 用户确认后再对真实 Git/SVN 做写入验收。本次只提供方案，尚未改写同步业务，也未触发真实 push/commit。
