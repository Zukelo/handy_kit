# Windows Bash 启动上下文与预检（0.1.4）

用户在 PowerShell 对绝对路径执行 `bash --noprofile --norc -n -- /d/.../sync_code-merge.sh` 返回 0，说明此 Bash 能打开并解析该文件，不能继续把错误归因于文件缺失或仅盘符格式。

## 执行流程

Windows Bash 任务默认增加受控入口：使用 --noprofile/--norc，忽略继承的 BASH_ENV、ENV、PWD；在 Bash 内通过 builtin cd 显式进入转换后的工作目录；用只读文件描述符实际打开主脚本，然后关闭检查描述符；最后 exec 当前 Bash，以文件方式执行主脚本和有序参数。

工作目录和脚本路径通过位置参数传入固定入口代码，不把用户路径/参数拼进 shell 代码，不使用 source/eval/stdin 执行用户脚本。实际脚本的 $0、BASH_SOURCE、退出码、输出捕获与受管 Job 保持文件执行语义。解释器路径按 Windows 组件规范化，避免混合分隔符。

如果任务显式配置 BASH_ENV 或 ENV，则保留原直接文件执行路径，避免用户初始化代码被两层 Bash 重复执行。其他显式环境覆盖继续生效。普通 sh/其他解释器不强加 Bash 专用选项。

## 错误区分

- Windows File::open 失败：显示原生读取错误。
- Bash 无法进入目录：错误输出含 `[HandyKit预检失败] Bash 无法进入工作目录`，退出码 125，并输出 Bash 的实际目录。
- Bash 无法打开脚本：错误输出含 `[HandyKit预检失败] Bash 无法打开脚本`，退出码 127，并输出 Bash 的实际目录。
- 预检通过后的错误来自后续文件执行阶段；保留原始 stderr，不用只显示的 Windows 请求目录冒充 Bash 的实际目录。仍需根据完整前缀/行号区分脚本打开与内部命令错误。

## 回归与交付

Windows 回归新增：故意设置错误的继承 PWD、从不匹配的原生工作目录启动受控入口，验证显式 Bash cd 后仍能执行；检查 $0 与 BASH_SOURCE 的文件身份；区分目录不可访问和脚本不可读。原 D 盘、参数、Git Bash、超时及 Job 管理用例继续运行。

本地仅生成在线 NSIS 安装包与独立 exe，保持 Windows GUI 子系统。用户实际桌面进程环境仍未在此复现，不能将标准 CI 通过等同于该机器已修复；安装后应确认版本 0.1.4，从旧版托盘彻底退出后复测，并保留完整执行消息与原始错误输出。
