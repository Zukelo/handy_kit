# 代码审查与全新基线整理（0.2.0）

日期：2026-11-23。范围为当前桌面前端、Tauri 命令/生命周期、定时器、插件宿主、原生同步、SQL 初始模型及质量检查。按全新程序使用场景审查，不保留 0.1.x 部署兼容分支。当前工作区已有的 Git Bash 后台执行、实时日志、原生插件功能继续保留。

## 1. 代码问题审查与修复

| 问题 | 修复 | 验证 |
|---|---|---|
| 定时器与同步插件重复维护 Windows 启动、进程树停止及编码转换，部分动作仍保留旧 Job 实现 | 提取 handykit-process；所有受管本地命令普通启动，统一停止和解码；独立应用保持启动请求语义 | 共享模块、调度器及 SCM 流程回归，Windows 测试代码交叉检查 |
| 原生同步继承 GIT_DIR/GIT_WORK_TREE 等变量，可能让 Git 操作父进程指定的其他仓库 | 原生 Git 命令清除仓库/索引/配置覆盖变量；通用脚本仍按用户显式配置继承环境 | 在隔离子测试中注入无效父 GIT_DIR/GIT_WORK_TREE，临时 Git → ZIP → SVN 完整流程仍通过 |
| 一个仓库的克隆目录可能与另一个仓库的 ZIP 输出重合或嵌套 | 预检同时检查克隆与 ZIP 路径关系，在任何 push 前拒绝冲突 | a 与 a.zip/sub 冲突回归 |
| 诊断进程达到输出捕获上限后关闭管道，可能干扰子进程正常完成 | 仅限制保留内容，继续排空后续输出；统一进程树清理 | 超过捕获上限的合成命令仍正常退出并保留限定输出 |
| 插件安装中断可能留下半成品目录，使插件列表和重装失败 | 先在私有暂存目录完整写入，再原子发布；未发布暂存不进入列表 | 模拟中断安装，已有插件列表及重新安装仍可用 |
| 每次日志脱敏重复编译多个正则表达式 | LazyLock 初始化固定规则一次 | 脱敏及 SCM 流程回归 |
| 磁盘记录读取后才检查体积，预先可能分配过大内存 | manifest/历史 JSON 通过受限读取后解析 | Rust 检查与存储回归 |

## 2. 运行逻辑审查与修复

| 问题 | 修复 | 验证 |
|---|---|---|
| 历史查询与执行结束写入竞争，可能把成功结果覆盖成中断 | 同一宿主目录排他锁；记录注册/完成与查询串行；查询只生成快照，不写历史；启动时统一恢复中断记录 | 重复查询不改变原文件，重启恢复仅发生一次 |
| 停止宿主与同步预留存在启动交错窗口 | 停止标记/取消与预留共用宿主锁 | 代码锁顺序审查与执行流程回归 |
| 最终记录持久化失败后，界面可能持续显示运行中 | 将失败结果保留在有上限的会话缓存，清除活动槽位；缺少控制器的运行记录显示结果未知 | 模拟目标记录无法写入，仍可查询失败结果，活动计数归零 |
| 插件历史只限制返回数量，磁盘文件持续增加；时钟变化还可能使活动运行排在旧记录后 | 保留最近 50 条完成记录，活动记录不删除且优先显示 | 55 条完成记录与 1 条活动记录的保留/排序回归 |
| 批量关闭标签时，后一个标签拒绝关闭，但前一个视图已被销毁 | 确认无副作用；所有确认完成后同步销毁并提交切换；过时切换请求作废 | 拒绝任一标签时均不销毁，旧关闭请求不能覆盖新状态 |
| 同步配置载入期间允许编辑，异步响应可能覆盖输入 | 首次载入期间禁用配置操作 | 前端回归 |
| 部分 SQLite、文件和原生对话框操作直接占用 async 命令执行线程 | 统一 blocking 后台调度，使用 Rust 类型构造计划，移除 JSON 自序列化构造 | 严格类型检查、应用 Windows Clippy |
| 无托盘时系统退出可能绕过活动任务保护；退出处理有重复分支 | 退出保护集中处理，活动任务必须完成或停止后才能退出；清除重复分支 | 静态生命周期审查与应用编译；无托盘现场行为仍需实测 |
| 同步日志轮询反复重置阅读位置，轮询错误也不可见 | 保留阅读位置/底部跟随，单独显示轮询错误 | 前端编译和现有日志回归 |

执行状态保持现有约定：前台脚本退出码 0 为成功、非 0 为失败；stderr 单独保留，其中可包含 Git 进度。外部操作不能由数据库事务回滚；未知的 push/commit 不自动重试。

## 3. 过时内容移除

- 移除内置 Bash 旧配置标记、迁移提示、专用兼容测试和无意义的解释器显示转换。
- 移除旧工作区存储版本回退，只使用当前格式。
- 合并为当前唯一初始 SQL，删除旧提醒模型的 settings/scheduled_tasks/task_runs 和 0002_timer_runtime.sql；不保留旧数据库备份迁移路径。
- 移除 CREATE_SUSPENDED、ResumeThread、自建 Job Object 的实现与依赖，所有受管调用共享当前普通启动策略。
- 移除 fs2，使用当前 Rust 最低版本支持的标准库排他文件锁。
- 插件只支持 API 2，检查插件与同步插件均更新为 0.2.0；移除 API 1 兼容分支。
- 移除临时 SQLite 文件头探测和冗长的沙箱排错消息，保留实际 SVN 校验、可读的程序/目录错误及正常业务日志。
- 静态原型 JS/CSS 移到 docs/prototypes/assets，当前执行源码不再混放原型实现。历史交付文档作为历史事实保留，并在文档入口与当前规范区分。

旧实现扫描覆盖当前 Rust/TypeScript/SQL 源码，未发现上述旧标记或旧进程实现。

## 4. 结构与规范

- `development/crates/process`：共用进程生命周期和输出解码。
- `development/crates/scheduler`：Cron、持久化、调度与受管动作。
- `development/crates/plugin-host`：单一插件契约、配置、工作流和执行记录。
- `development/apps/desktop/src-tauri/src/blocking.rs`：阻塞命令执行入口。
- `development/apps/desktop/src/app/lifecycle.ts`：标签关闭事务。
- `development/apps/desktop/src/plugins/model.ts`：插件界面共享类型，工作流顺序以插件包为准，不在界面重复硬编码。
- 前端统一为锁定的 Prettier 3.6.2 格式；Rust 使用 rustfmt；增加 EditorConfig、TypeScript 未使用项检查、CI 格式及 Clippy 零警告检查。
- README、开发说明、插件说明、数据库文档与当前代码对齐；有用的示例和设计历史仍独立保留。

首次启动使用系统应用数据目录的 `runtime/` 子目录，没有预置任务或插件。旧布局不读取、不迁移、不删除。0.1.x 数据库不属于此新基线；后续本基线内的 SQL 变更仍应追加迁移并校验。
