# 定时器严格使用配置的解释器（0.1.5）

日期：2026-11-21。

## 修复范围

脚本任务在 Windows 上直接使用配置的解释器路径创建进程。不再将 git-bash.exe 替换为 usr/bin/bash.exe 或 bin/bash.exe，也不再将 bin/bash.exe、bin/sh.exe 替换为 usr/bin 下的文件。不再按解释器文件名拒绝保存配置；仍检查绝对路径、文件存在和可执行类型。原配置无需重新保存，手动执行与定时触发使用同一执行入口。

配置页同步说明实际行为。已有 Bash 专用预检仅在用户选择 bash.exe 时使用；选择 git-bash.exe 时不进入 Bash 专用预检。参数继续按独立 argv 传递，工作目录、环境变量覆盖、超时及受管进程机制保留。

终端启动器可能打开窗口，其退出码和输出不一定代表脚本执行完成。此修复保证配置的启动入口不被替换，不宣称已经验证 Cloudaemon 的沙箱继承或终端启动器的完整进程生命周期。

## 回归

Windows 新增命令构造回归：同目录同时存在 git-bash.exe 和 usr/bin/bash.exe 时，仍选择配置的 git-bash.exe；检查含空格脚本名、中文参数、空参数和字面变量参数。原后台 Bash 输出和 D 盘用例改为显式配置 usr/bin/bash.exe，不再依赖自动替换。

Windows/Cloudaemon 手工验收：彻底退出旧程序，启动修复构建；保留原 git-bash.exe 配置，分别手动运行和定时触发同一脚本，确认能读取沙箱内文件，并核对窗口、运行记录和脚本实际完成情况。本机为 macOS，无法替代该环境验收。
