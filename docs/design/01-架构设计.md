# 架构设计

## 技术选择

桌面外壳 Tauri 2；核心逻辑 Rust；界面建议 TypeScript + Vite，初始化保持原生 DOM，暂不引入大型界面框架。持久化选 SQLite。

```text
界面（本地静态资源）
    ↓ 类型化 invoke / 事件
Tauri 命令层（输入校验、错误映射）
    ↓
工具服务 / 调度服务
    ↓
SQLite 存储与版本迁移
```

初始源码在 `development/apps/desktop/`。业务增长后将纯 Rust 工具库、存储、调度拆为 `development/crates/`，不要提前制造空模块。

## 边界

- Rust 承载最终工具算法、cron、调度与数据库；当前网页 JSON 功能只是骨架示例。
- IPC 采用结构化结果；错误提供类别、中文信息及可选位置；大输入在工作线程处理。
- 数据库仅由 Rust 访问；前端不得传入任意 SQL 或任意文件路径。
- 调度器显式指定 IANA 时区；重启时只计算下一次触发，默认跳过错过的执行；夏令时重复时段按计划时间去重。具体语义须 P2 测试确认。
- Tauri capability 使用最小权限；不加载远程网页，不启用 shell 插件。
- CSP 限制本地资源；禁止 XML 外部实体和网络解析；日志不记录工具原文。

## 数据布局

仓库 `database/` 存 SQL 与开发数据；安装后数据库存 Tauri app_data_dir 下的 `handykit.sqlite3`。用户备份必须明确选择位置。迁移前备份，版本只追加，不修改已发布迁移。
