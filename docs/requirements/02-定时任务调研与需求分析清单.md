# 定时任务小工具：调研与需求分析清单

版本：讨论稿 v0.1

日期：2026-11-20

状态：需求分析，尚未进入实现；P0/P1 与默认值均为建议，未经用户确认不视为最终验收基线。

## 1. 本轮已确认需求与范围变化

|编号|用户明确要求|
|---|---|
|CONF-01|任务可配置 Cron 表达式。|
|CONF-02|Cron 支持界面化配置和表达式生成。|
|CONF-03|可配置真正执行的动作，例如 sh 脚本、exe 程序、macOS app。|

变化说明：早期需求中的“仅应用内提醒”和“不默认执行 shell”属于初始化时的建议，现已被本轮脚本/程序执行需求扩展；不再作为排除脚本执行的限制。“驻留”已实现，但当前调度器、任务业务和生产数据库接入仍未实现。

本轮仅研究和整理需求，不运行用户脚本、不添加系统计划任务、不修改数据库迁移或应用代码。

## 2. 调研结论

### 2.1 Cron 方言必须显式指定

传统 Unix Cron 是五个时间字段，Quartz 通常是六/七字段，包含秒和可选年份；两者的星期编号、特殊符号也存在差异。不能根据字段数量自动补零后就认为含义等价。[Cronie 维护者手册](https://github.com/cronie-crond/cronie/blob/master/man/crontab.5)、[Quartz 官方格式说明](https://www.quartz-scheduler.org/documentation/quartz-2.5.x/tutorials/crontrigger.html)

建议首版采用明确的 `unix5`：分钟、小时、日期、月份、星期，最小粒度一分钟；是否扩展秒级及 Quartz 列为待确认项。

### 2.2 可视化生成不能只做表达式拼接

需要形成“表单配置 → 表达式 → 中文说明 → 未来触发时间”的一致链路，并支持高级输入返回表单。不能无损表示的表达式应保留高级模式，禁止静默转换或丢弃字段。

Unix 的日期和星期同时受限时通常采用 OR；字段步长也有字段边界，例如 `*/23` 小时表示每天的 0 点和 23 点，不能宣传为严格间隔 23 小时。夏令时可能产生不存在或重复的本地时间。[Cronie 维护者手册](https://github.com/cronie-crond/cronie/blob/master/man/crontab.5)

### 2.3 执行脚本与打开 GUI 应用应分为两种结果模型

建议把动作分成 `script`、`executable`、`application`，再区分：

|执行模式|能确认什么|适用情况|
|---|---|---|
|受管进程|子进程启动、退出码、耗时、stdout/stderr；可定义超时和取消|sh 脚本、命令行 exe、Linux 可执行程序|
|应用启动请求|操作系统接受启动/激活请求；不能据此判断应用业务完成|macOS .app、按独立应用模式打开的 GUI exe|

macOS 的 `open --args` 支持向启动的应用传入 argv，`-n` 表示请求新实例；Apple 的 OpenConfiguration 也将 arguments 定义为新实例启动参数。已运行应用是否接收新参数、是否支持多实例，必须以目标应用实测为准，不能承诺所有 app 一致。此处“启动成功不等于业务执行完成”是基于启动 API 边界作出的产品设计判断。[Apple OpenConfiguration](https://developer.apple.com/documentation/appkit/nsworkspace/openconfiguration)、本机 macOS `man open`（2026-11-20 核对）

### 2.4 程序、参数、工作目录应分别配置

Rust 的 `Command::args` 对普通程序传递独立参数，不会自动执行 shell 的管道、重定向和变量替换；Windows 的 cmd/bat 参数规则需要单独处理。因此建议以有序参数列表为真源，显示的命令行只做预览，不反向当作一条 shell 命令执行。[Rust Command 官方文档](https://doc.rust-lang.org/std/process/struct.Command.html)

Windows 任务执行接口本身也分别定义可执行路径、参数和工作目录，可作为字段划分参考；这不代表小工坊首版必须接入 Windows Task Scheduler。[Microsoft IExecAction](https://learn.microsoft.com/en-us/windows/win32/api/taskschd/nn-taskschd-iexecaction)

### 2.5 托盘驻留不等于系统服务

建议首版调度运行在小工坊 Rust 进程中：窗口隐藏继续调度；彻底退出、注销、关机后不运行；休眠期间不承诺触发。若需要应用退出后仍执行，则需单独设计系统级后端及桌面会话问题。

系统后端并不天然同义：Apple 对 launchd 日历任务和 cron 的睡眠恢复行为有不同说明，systemd timers 也有自己的精度和补偿配置；不能简单把同一 Cron 字符串原样下发到各系统并宣称行为一致。[Apple 定时任务指南](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html)、[systemd.timer 官方手册](https://www.freedesktop.org/software/systemd/man/latest/systemd.timer.html)

GUI 启动还依赖登录用户的桌面会话；Windows 官方计划任务也区分交互用户条件。[Microsoft schtasks create](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/schtasks-create)

## 3. 建议首版需求清单（P0）

以下均为待开发功能；标记“用户要求”表示直接来自本轮需求，其余为完成该能力所需的配套建议。

### 3.1 任务管理与工作区

|编号|需求|来源|验收要点|
|---|---|---|---|
|TASK-001|新增、编辑、复制、启用、暂停、删除任务|配套建议|新任务默认保存为暂停；复制生成新 ID 且默认暂停。|
|TASK-002|任务名称、说明与搜索筛选|配套建议|按名称、动作类型、启用状态过滤；空列表和无结果状态明确。|
|TASK-003|任务列表与详情|配套建议|展示计划摘要、动作目标、下次执行、最近结果；配置状态与运行状态分开。|
|TASK-004|遵循现有 Tab 工作区|既有设计|菜单打开工具保持唯一主 Tab；列表进入详情后可返回，未保存修改不被静默丢弃。|
|TASK-005|配置持久化与启动恢复|配套建议|App 重启保留定义；无效路径或缺失解释器需显示问题，不静默变成其他动作。|

### 3.2 Cron 可视化配置

|编号|需求|来源|验收要点|
|---|---|---|---|
|CRON-001|常用周期生成器|用户要求|支持每 N 分钟、每小时指定分钟、每天指定时间、每周多选星期、每月多选日期；不必手写表达式。|
|CRON-002|字段级可视化编辑|用户要求|五个字段分别提供每个值、指定值/多选、范围、步长；值域和组合即时校验。|
|CRON-003|表达式显示、复制与高级输入|用户要求及配套建议|生成结果可复制；粘贴合法表达式后解析；不支持方言明确报错。|
|CRON-004|表单与表达式的无损往返|配套建议|支持子集往返后未来触发时间一致；复杂列表/步长组合不能回填时保持高级模式和原表达式。|
|CRON-005|中文解释与未来十次触发预览|配套建议|同时显示时区、日期和星期；报错后清除旧预览，不能继续显示上一个表达式结果。|
|CRON-006|独立任务时区|配套建议|默认保存创建时的系统 IANA 时区；可选其他时区；后续系统时区变化不暗中改变已保存任务。|
|CRON-007|无触发与边界提示|配套建议|识别无效日期组合；每月 31 日不自动挪到月底；星期 0/7 的 Sunday 含义一致。|
|CRON-008|解析语义一致|配套建议|生成、解释、预览与实际调度共用 Rust 解析语义；前端不能另外实现一套不同的计算规则。|

建议首版语法：数字、`*`、`,`、`-`、`/`；星期接受 0/7 为周日并规范化输出。月份/星期英文名是否接受由解析器能力验证后决定。`? L W #`、年份、`@reboot` 等不默认纳入 `unix5`。

“每周一至周五”不等于法定工作日；节假日和调休需要独立日历，暂列 P1。

普通周期表单避免同时限制“日期”和“星期”；高级模式若两者都限定，按 Unix OR 语义明确说明。步长按日历字段解释，严格“自某时刻起每隔 90 分钟”属于另一种间隔触发器，不伪装成当前 Cron 模式。

### 3.3 任务动作与入参

|编号|需求|来源|验收要点|
|---|---|---|---|
|EXEC-001|选择动作类型|用户要求|运行脚本、运行可执行程序、打开应用三类；切换类型时不把旧字段误用于新动作。|
|EXEC-002|sh 脚本文件与解释器|用户要求|选择脚本和解释器路径；支持 sh/bash/zsh 的显式选择；缺失解释器给出可操作提示。|
|EXEC-003|exe / 原生可执行程序|用户要求|支持 Windows exe、Unix 原生可执行文件；路径与权限检查、启动错误单独记录。|
|EXEC-004|macOS .app 启动|用户要求|选择 app 包；配置启动参数以及复用/新实例策略；结果明确为启动请求结果。|
|EXEC-005|有序参数编辑器|用户要求|参数可新增、删除、排序；每行一个独立参数，保留空参数、空格、中文和特殊字符。|
|EXEC-006|工作目录|配套建议|受管脚本/程序默认目标所在目录，可改绝对路径；不使用安装目录作为隐含工作目录。|
|EXEC-007|环境变量覆盖|配套建议|按 key/value 配置普通环境变量；说明桌面进程环境与交互终端不同；不自动读 shell profile。|
|EXEC-008|配置检查与命令预览|配套建议|显示实际目标、解释器、工作目录、参数边界和时区；预览不执行任何动作。|
|EXEC-009|立即执行|配套建议|由用户主动触发真实执行；明确是否使用已保存配置；首版建议仅执行已保存的配置。|
|EXEC-010|类型相关的完成语义|配套建议|受管任务按退出码结束；GUI 启动请求不伪装为脚本完成，也不默认等待用户关闭应用。|

参数例子：`--output`、`/Users/me/Build Output`、空字符串，必须作为三个参数保存；输入中的引号只是参数字符，不应要求用户手工再套一层引号。`$HOME`、`%TEMP%`、`~`、通配符默认不展开。需要 shell 语法的复杂逻辑写入用户选择的脚本文件。

首版建议选择现有脚本文件，暂不内置脚本编辑器或“一行任意 shell 命令”输入框；这些属于后续扩展，不影响用户运行自己维护的 sh 文件。

### 3.4 调度、生命周期与执行控制

|编号|需求|来源|验收要点|
|---|---|---|---|
|RUN-001|Rust 后台调度|配套建议|主窗口隐藏、切换工具或 WebView 不活跃不影响调度；不依赖页面 setInterval。|
|RUN-002|启停立即生效|配套建议|暂停阻止后续计划启动；默认不终止已在运行的受管进程，停止运行另设操作。|
|RUN-003|同任务重叠策略|配套建议|建议默认单任务串行，遇到上一轮未结束时跳过并记录原因；手动执行同样遵循策略。|
|RUN-004|全局并发限制|配套建议|不同任务有总并发上限；饱和后不无限积压；默认上限和跳过/队列策略待确认。|
|RUN-005|超时与取消|配套建议|只适用于受管任务；超时与人工取消有不同结果；需验证子进程树处理，不误杀用户独立打开的应用。|
|RUN-006|重启/唤醒后错过的计划|配套建议|建议默认跳过，显示遗漏摘要；定义正常触发宽限，不能把轻微调度延迟当成遗漏；“最近一次补跑”列为后续能力。|
|RUN-007|时钟调整与夏令时|配套建议|时钟前跳/回拨不造成同一计划无意重复；不存在时刻跳过；重复本地时刻的执行次数必须固定。|
|RUN-008|单一调度所有者|配套建议|多窗口/重复启动/恢复竞争时同一用户数据目录仅一个调度所有者，不重复派发。|
|RUN-009|运行中编辑/删除|配套建议|新配置只影响未来启动；本轮保存配置快照；删除不隐含杀进程，操作需告知运行中状态。|
|RUN-010|彻底退出时的任务处理|配套建议|停止新调度；受管任务未结束时提供继续后台、等待完成后退出或停止后退出；已独立打开的 GUI 应用不自动关闭。|
|RUN-011|崩溃恢复与未知结果|配套建议|历史 running 恢复后标为中断/结果未知；不自动重跑可能已产生副作用的任务，不承诺外部动作严格执行一次。|

重试建议默认关闭，失败后允许手动重试；自动重试、退避和最大次数作为 P1。超时建议可选，未设置时不限时；不以一个任意固定超时终止所有长任务。

调度去重建议使用任务 ID、配置版本和计划触发时刻；夏令时若选择“同一本地时刻只执行一次”，还须在时间解释层选择首次出现，不能只依赖两个不同 UTC 时间的唯一约束。

### 3.5 执行记录与必要约束

|编号|需求|来源|验收要点|
|---|---|---|---|
|HIST-001|每次启动尝试可追溯|配套建议|保存任务、配置版本、计划/手动来源、计划与实际时间、耗时及结果。|
|HIST-002|受管进程输出|配套建议|分别记录 stdout/stderr、退出码、启动失败、超时、取消；不等到进程结束才无限缓存输出。|
|HIST-003|GUI 结果单独展示|配套建议|显示“启动请求成功/失败”等结果；退出码为空不是默认成功码 0。|
|HIST-004|日志保留和清理|配套建议|总容量、单次输出上限和保留期可定义；截断要有标识；无法解码内容不能导致界面崩溃。|
|HIST-005|删除后的历史|配套建议|建议软删除任务或保留运行快照，避免删除一个任务把用于排错的历史全部抹掉。|
|CTRL-001|按当前用户身份执行|配套建议|不默认提升为管理员/root，不自动改系统策略；权限不足记录为失败。|
|CTRL-002|执行意图和参数边界明确|配套建议|启用任务展示执行摘要；入参按列表传递，不拼接 shell 字符串；无需每次触发重复确认。|
|CTRL-003|敏感配置与日志|配套建议|参数/环境变量支持敏感标记与界面遮罩；不得把普通 SQLite/JSON 存储宣传为加密；任意程序输出无法保证自动完全脱敏。|

## 4. 跨平台动作能力建议

|动作|macOS|Windows|Linux|首版建议|
|---|---|---|---|---|
|sh 脚本|显式选择系统或用户解释器|需要用户已有的兼容解释器；不假定系统内置 sh|显式选择系统或用户解释器|P0；Windows 缺解释器时不可启用此任务|
|可执行程序|Mach-O / CLI|exe / CLI|ELF / CLI|P0，参数和工作目录独立配置|
|GUI 应用|app 包，走系统应用启动机制|GUI exe，可选择独立启动模式|GUI 原生可执行程序，要求桌面会话|P0，记录启动结果而非业务结果|
|PowerShell / bat / cmd|取决于额外运行环境|需独立的解释器与转义适配|取决于额外运行环境|P1 待确认，不能按普通 exe 规则统一拼接|
|WSL 脚本|不适用|发行版、路径映射、环境需独立适配|不适用|P1，不自动把 Windows 路径当 Linux 路径|
|Linux .desktop / 文件关联启动|不适用|不适用|需桌面启动器适配，不是直接执行文本文件|P1 待确认|

macOS app 的 cwd、环境覆盖、输出捕获不能默认宣称与受管进程一致；首版 UI 应按实际适配能力显示字段，不支持的能力应明确禁用并说明。

## 5. 页面与操作流程建议

### 5.1 主 Tab

`时间与任务 → 定时任务 → 任务列表 / 任务详情 / 执行记录`

保持在现有工作区，不弹独立主窗口。列表工具栏提供新增、搜索、状态筛选；每行提供编辑、立即执行、启停和更多操作。

### 5.2 新建/编辑任务

|区域|内容|
|---|---|
|基本信息|名称、说明、保存后是否启用。|
|执行计划|周期预设、自定义字段、高级表达式三种入口；时区、中文说明、未来十次触发。|
|执行动作|动作类型、目标文件、解释器、有序参数、工作目录、普通环境变量。|
|运行策略|受管/应用启动模式、重叠策略、超时、遗漏策略；不适用的字段隐藏。|
|核对与保存|计划摘要、动作摘要、参数预览；保存为暂停或保存并启用。|

预览操作不执行；“立即执行”清楚标识为真实动作。离开未保存编辑时应可保存、放弃或继续编辑，避免工具 Tab 关闭丢失配置。

## 6. 与现有工程和数据库的差距

|当前实际情况|需求影响|后续工作|
|---|---|---|
|工具仅占位，无调度/执行服务|不能在前端加一个定时器即视为完成|增加 Rust Cron 服务、调度器、执行器与查询 IPC。|
|首页状态保存在 localStorage|不适合存调度运行权和执行日志|按既有方案接入 SQLite，UI 通过命令层访问。|
|scheduled_tasks.action_type 被 CHECK 限制为 reminder|不能直接存脚本/exe/app 类型|追加新版本迁移，保留既有迁移校验和；按需重建受约束表。|
|task_runs 状态缺少启动请求/超时/取消/中断语义，也无完整退出码字段|日志无法准确表达新动作|设计统一结果字段、执行模式及配置快照，再追加迁移。|
|现有任务删除为级联删除运行记录|与建议保留历史冲突|在需求确认后改为软删除/独立快照，不直接改旧迁移。|
|此前执行与运行生命周期未设计|关闭隐藏和彻底退出需要区分|在现有 desktop 生命周期中接入调度及受管任务退出策略。|
|Windows/Linux 尚未做单实例协调|驻留时重复启动可能重复调度|任务阶段增加单实例与数据库运行权约束。|

建议核心字段包括：任务 ID/名称/说明/配置版本/启用状态；Cron 方言、表达式、IANA 时区；动作类型、执行模式、程序或 app 路径、解释器、参数数组、工作目录、环境覆盖；重叠、超时、遗漏策略；创建/更新时间。运行记录保存动作快照，敏感值处理另行设计。

以上为数据需求，不是已批准的最终表结构；本轮不创建新迁移。

## 7. 调度方式与解析器选型建议

|方案|优点|限制|建议|
|---|---|---|---|
|小工坊 Rust 进程内调度|三平台可用同一语义，直接配合现有托盘和任务记录|彻底退出后不运行，休眠会错过|首版推荐，须确认用户是否接受此生命周期。|
|封装各 OS 调度器|可扩展应用未运行时执行的场景|Cron 映射、权限、桌面会话、日志与卸载清理更复杂|若“退出后仍运行”为硬需求，则单独立项。|

Rust Cron 解析候选可调研 [croner-rust](https://github.com/Hexagon/croner-rust)，其维护者说明支持多种字段及扩展语法；这并不代表小工坊必须全部开放。正式选型须先验证 `unix5` 子集、日期/星期逻辑、时区和夏令时，以及搜索无结果的边界；本轮不锁定依赖或版本，也不采用仓库宣传替代实测。

## 9. 后续扩展清单（建议 P1）

- 秒级/Quartz 方言、最后一天/第几个星期几等复杂规则。
- 一次性任务、严格固定间隔任务，不能与 Cron 日历调度混为一谈。
- 节假日、调休和业务日历。
- 内置脚本编辑器、脚本模板、参数变量与执行时间变量。
- PowerShell、bat/cmd、WSL 与 .desktop 专用执行适配。
- 遗漏最近一次补跑、自动重试、队列与并行策略。
- 系统级后台调度、登录自启、失败通知。
- 任务导入导出、分组、批量启停、系统凭据存储。
- 多动作顺序编排、依赖关系与远程执行；首版建议一项任务对应一个动作。

## 10. 最小验收场景清单

- [ ] 界面配置“每周一至周五 09:00”生成 `0 9 * * 1-5`，中文说明和未来十次一致。
- [ ] 每小时第 15 分钟、每月指定日期、多值/范围/步长可生成、保存和重开。
- [ ] 高级表达式可无损回填或明确保留高级模式；六七字段不被误当五字段。
- [ ] 月末 31 日、闰日、日期/星期 OR、夏令时与时区切换有约定一致的结果。
- [ ] sh 脚本能收到独立参数，包括中文、含空格路径、空字符串和引号字符。
- [ ] Windows exe / macOS app / Linux 原生程序分别完成对应平台用例。
- [ ] 缺解释器、文件被移动、没有权限、工作目录不存在均有准确错误。
- [ ] GUI 应用启动显示“启动请求成功”，不谎报其内部业务成功；已运行应用传参按约定处理。
- [ ] 窗口隐藏后按时执行；彻底退出停止调度；唤醒/重启按遗漏策略处理。
- [ ] 任务重叠、全局饱和、暂停、手动执行、运行中编辑和删除按已确认策略处理。
- [ ] 受管任务退出码、超时、取消、子进程和大输出可追溯且不会无限占用内存/磁盘。
- [ ] 重复启动小工坊不重复派发；崩溃后的未知结果不自动执行第二遍。
- [ ] 数据库升级不修改旧迁移，恢复定义与历史后仍可继续调度。
