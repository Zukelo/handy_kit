# Git Bash 沙箱上下文诊断

将 `check-context.sh` 复制到 Windows 上可写、且小工坊能够选择到的目录。复制一份原定时任务并保持暂停，仅将目标改为该脚本，保留原 `git-bash.exe` 解释器、工作目录和环境变量，然后点击手动执行。脚本会在自身所在目录生成唯一的 `handykit-context-*.log`，即使终端退出，文件仍保留。

可在有序参数中添加一个已知沙箱内文件的路径；Git Bash 格式例如 `/d/project/sandbox-only.txt`，它只检查是否存在及可读，不读取文件内容、不列目录。报告不输出完整环境、PATH 或凭据。

如未生成报告，不代表一定脱离沙箱：也可能尚未进入脚本、解释器启动失败或目录不可写。此时需要小工坊执行记录中的执行消息、退出码和错误输出。

脚本使用 Bash 内建命令，避免 PATH 缺少工具时诊断本身失败。不暂停等待输入，不修改原脚本或配置。脚本执行时的交互标志不应直接与手动交互终端等同；应结合 MSYSTEM、工具位置、初始化文件可读性及已知文件可见性判断。

0.1.13 起，Windows 定时「脚本」动作采用普通子进程启动，无挂起恢复和自建 Job。请先用本诊断脚本手动验证，再恢复业务脚本。git-bash.exe 的启动器退出结果不能替代本报告或业务产物；普通启动的取消为尽力终止进程树，不保证宿主意外退出时自动清理全部后代。

0.1.14 起，定时脚本所选解释器为 git-bash.exe 时使用启动器后台命令模式（登录、非交互 Bash），不打开 Mintty，日志与退出码回传小工坊。可先执行 `live-logs.sh` 验证实时标准输出/错误；默认退出码 0，传一个独立参数 `23` 验证失败退出码。此脚本不读写业务文件；每秒输出进度，共三秒。详情见 docs/delivery/21-GitBash后台实时日志.md。
